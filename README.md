# JobTrail

AI-powered job application tracker — track applications through an interview pipeline, generate tailored cover letter drafts, and score how well your resume matches each job.

**Live demo:** _coming soon — add the Render URL here after deploying (see [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md))_

## Stack

React (Vite) · FastAPI · PostgreSQL · SQLAlchemy · Pydantic · Claude API · Docker · Render

## Features

- **Pipeline dashboard** — applications grouped Applied → Interview → Offer → Rejected, with a validated create/edit form
- **Cover letter drafts** — Claude writes a letter tailored to the job description, using only experience that's actually in your resume; pick a tone (professional / enthusiastic / concise)
- **Resume match score** — Claude extracts the job's key skills and scores your resume 0–100, listing matched and missing keywords; the latest score shows on each card
- **Cost controls** — identical AI requests are served from a Postgres cache; real API calls are rate-limited per client (sliding window) and capped per day overall
- Loading and error states throughout, plus an error boundary around the app

## Architecture

```
Browser (React SPA)
   │  fetch, JSON
   ▼
FastAPI ── main.py ........ CRUD for /applications
   │       ai.py .......... /applications/{id}/cover-letter, /match-score
   │       prompts.py ..... versioned prompt templates
   │       ai_cache.py .... DB cache + daily cap  ──► Claude API
   │       rate_limit.py .. per-client sliding window
   ▼
PostgreSQL ── applications · match_scores · ai_responses
```

A few decisions worth calling out:

- **Prompts are versioned templates**, not inline f-strings. The version is part of the cache key, so changing a prompt can never serve answers generated by the old one.
- **User text is treated as data.** Job postings and resumes are wrapped in tags and the system prompt tells Claude not to follow instructions inside them, which blunts prompt injection from a malicious posting.
- **Claude's JSON is validated, not trusted.** The match-score reply is parsed defensively and checked with Pydantic (score must be 0–100). A malformed reply returns 502 rather than saving a made-up number.
- **Rate limits only apply to cache misses**, so re-opening a result is always free. The per-client limiter is in memory (fine for one instance; Redis would be next at scale); the daily cap is counted in Postgres, so it holds across restarts.
- **Tests never call the real API.** The Claude client is a FastAPI dependency that tests replace with a fake.

## API

| Method | Path | What it does |
| --- | --- | --- |
| `GET` | `/applications` | List applications (with latest `match_score`) |
| `POST` | `/applications` | Create an application |
| `PATCH` | `/applications/{id}` | Update any subset of fields |
| `POST` | `/applications/{id}/cover-letter` | `{resume_text, tone}` → cover letter draft |
| `POST` | `/applications/{id}/match-score` | `{resume_text}` → score + matched/missing keywords |
| `GET` | `/applications/{id}/match-score` | Last saved score breakdown |

Interactive docs at `/docs` when the API is running.

## Running it

### Option 1 — Docker (everything at once)

```bash
cp .env.example .env          # add your ANTHROPIC_API_KEY
docker compose up --build
```

- App: http://localhost:8080
- API: http://localhost:8000 (docs at `/docs`)

Data lives in the `pgdata` volume; `docker compose down -v` wipes it.

### Option 2 — Local dev (hot reload)

Prerequisites: Python 3.13+, Node 18+, PostgreSQL running locally.

**Backend**

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

createdb jobtrail             # only needed once
cp .env.example .env          # add your ANTHROPIC_API_KEY

uvicorn main:app --reload
```

**Frontend**

```bash
cd frontend
npm install
npm run dev                   # http://localhost:5173
```

The CRUD features work without an API key; the AI buttons return a clear "not configured" error until one is set.

### Configuration

All backend settings are environment variables (see `backend/config.py`):

| Variable | Default | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql+psycopg2://localhost/jobtrail` | Postgres connection |
| `CORS_ORIGINS` | `http://localhost:5173` | Comma-separated allowed frontend origins |
| `ANTHROPIC_API_KEY` | — | Enables AI features |
| `ANTHROPIC_MODEL` | `claude-sonnet-5-5` | Claude model |
| `AI_RATE_LIMIT` / `AI_RATE_LIMIT_WINDOW_SECONDS` | `10` / `3600` | Real API calls per client per window |
| `AI_DAILY_LIMIT` | `200` | Real API calls per 24h, all clients |
| `AI_CACHE_TTL_HOURS` | `168` | How long cached replies are reused |

The frontend reads `VITE_API_URL` at **build** time (default `http://localhost:8000`).

## Tests

```bash
cd backend
source .venv/bin/activate
pytest
```

39 tests cover CRUD, validation, both AI endpoints (with a fake Claude client), prompt rendering, caching, and rate limiting (including a fake clock for the sliding window). They run against SQLite, so no database server is needed.
